  3. 初期設定を行う管理者のGoogleアカウントと、GitHubアカウントをご用意ください。ゲームで使う教員ログインは、共通ID＋パスワードです。

実端末でのオンライン対戦は、以下の初回設定を済ませてから使用できます。設定前に演出・操作を試したい場合は、同梱の demo.html を開いてください。

教員のPCが集計と発表の進行役です。授業中はオンラインで画面を開いたままにしてください。PCが切断中でも、Firebaseに保存済みの提出は残り、再接続後に進行を再開できます。
02 / FIREBASE

対戦データの保存先を作る。

A. 新しいプロジェクトを作成

  1. Firebaseコンソールを開き、管理者のGoogleアカウントでログインします（Firebaseの初期設定・管理時だけ必要です）。
  2. 「プロジェクトを作成」または「プロジェクトを追加」を押します。名前は例として no15-classroom とします。
  3. Google Analyticsは、このゲームには必須ではありません。有効化を求められた場合は無効のまま進められます。
  4. 料金プランはSpark（無料）を使用します。Cloud Functionsは使いません。

すでに他のサービスを動かしているプロジェクトとは分けると、ルール設定が混ざらず管理しやすくなります。

B. 2種類のログインを有効化

  1. 左メニューで「構築（Build）」→「Authentication」→「始める」を選択します。
  2. 「Sign-in method／ログイン方法」タブで「匿名」を選び、「有効にする」→「保存」を押します。
  3. 同じ画面で「メール／パスワード」を選択し、有効にして保存します。メールリンク認証は不要です。Googleログインの有効化も不要です。

C. Realtime Databaseを作成

  1. 左メニュー「構築（Build）」→「Realtime Database」→「データベースを作成」を押します。
  2. ロケーションを選びます。日本から利用する場合の候補はシンガポール（asia-southeast1）です。作成後は変更できません。
  3. セキュリティ設定は「ロックモードで開始」を選びます。
  4. 作成後の「データ」タブに表示されるURLを控えます。例：https://プロジェクト名-default-rtdb.asia-southeast1.firebasedatabase.app

D. アクセスルールを設定

  1. ZIP内の database.rules.json をテキストエディットなどで開きます。
  2. ⌘A → ⌘Cでファイル全体をコピーします。
  3. FirebaseのRealtime Database →「ルール」タブを開きます。
  4. エディター内の既存の内容をすべて選択し、コピーした内容に置き換えます。
  5. 「公開（Publish）」を押します。エラーが出ていないことを確認します。
ルールは必ず同梱ファイルの内容を使用してください。未発表カードを守るため、全員に読み書きを許可する設定にはしません。

E. 教員共通のIDとパスワードを登録

  1. 共通IDを決めます。3〜32文字の半角英数字・ハイフン・アンダースコアを使用し、先頭は英数字にします。大文字は小文字として扱います。例：teacher。
  2. Authenticationの「Users／ユーザー」→「ユーザーを追加」を開きます。メール欄には小文字のID＋@teacher.no15.invalidを入力します。例：teacher@teacher.no15.invalid。これは認証内部用の識別子で、メールの受信は不要です。
  3. 十分に長い共通パスワードを設定して登録します。パスワードはこのページやGitHubのファイルに書かないでください。
  4. 登録したユーザーのUIDをコピーします。
  5. Realtime Databaseの「データ」で、ルート直下に teachers、その子にコピーしたUIDを追加し、値を真偽値の trueにします。文字列の "true" ではありません。構造は teachers / UID / true です。
ゲーム画面にはID（例：teacher）とパスワードだけを入力します。同じIDでログインした教員は同じルーム一覧を利用できます。同じルームの進行操作は1台で行ってください。アカウントを作っただけでは教員権限は付かず、上記のUID登録も必要です。共通パスワードの変更は管理者がAuthenticationで行います。識別子のメール宛てには再設定メールを受信できません。

F. Webアプリを登録

  1. プロジェクト概要の「</>」（ウェブ）を押します。見当たらない場合は、歯車 →「プロジェクトの設定」→「全般」→「マイアプリ」から追加します。
  2. アプリのニックネームを NO.15 Web とし、「アプリを登録」を押します。
  3. SDK設定の「構成／Config」に表示される firebaseConfig をコピーします。あとで③の補助ツールへ貼り付けます。

生成したコードを表示

この補助ツールは入力内容を外部へ送信せず、このページ内で変換します。ファイルは通常「ダウンロード」フォルダーに保存されます。

  1. 「config.jsを生成して保存」を押します。

04 / GITHUB PAGES

ファイルをアップロードして公開。

A. リポジトリを作成

  1. GitHubの新規リポジトリ作成画面を開きます。
  2. Repository nameは例として NO15、公開範囲はPublicを選びます。READMEの追加を選択して作成すると、最初からmainブランチが用意されます。
  3. 「Create repository」を押します。

B. ファイルをアップロード

  1. リポジトリの「Add file」→「Upload files」を押します。
  2. 展開したゲームフォルダーを開き、中にあるファイルとフォルダーをまとめてアップロード欄へドラッグします。vendor や tests もフォルダーのままで構いません。
  3. ③で作った自分用の config.js が含まれていることを確認します。
  4. 画面下の「Commit changes」で確定します。
  5. リポジトリの一番上の階層に index.html があることを確認します。
ゲームフォルダー自体を1つのフォルダーとして追加すると、URLの階層が増えてしまいます。index.htmlがリポジトリの直下にある状態にしてください。node_modulesは同梱していません。

C. GitHub Pagesを有効にする

  1. リポジトリの「Settings」→左メニュー「Pages」を開きます。
  2. Build and deploymentのSourceを「Deploy from a branch」にします。
  3. Branchを「main」、フォルダーを「/ (root)」にして「Save」を押します。
  4. 公開処理が完了すると「Your site is live at…」にURLが表示されます。初回は数分かかる場合があります。

D. ログインを許可するドメインを追加

  1. Firebaseコンソールの「Authentication」→「設定（Settings）」→「承認済みドメイン（Authorized domains）」を開きます。
  2. 「ドメインを追加」を押し、公開URLのドメインだけを入力します。
  3. 例：公開URLが https://yourname.github.io/NO15/ なら、入力するのはyourname.github.ioです。https:// や /NO15/ は含めません。
05 / FIRST CONNECTION

最初に、小さな対戦で確認。

  1. 教員PCで公開URLを開きます。
  2. 「教員IDでログイン」でログインし、参加上限とルーム名を設定して「ルームを作成」を押します。
  3. 「QRコードを表示」を押し、2台以上のスマートフォンで読み取ります。
  4. それぞれ異なるニックネームで参加し、教員画面に名前がそろうことを確認します。
  5. 「ルールを設定して開始」を押します。最初の動作確認は、提出時間0（時間無制限）、イベントなしにすると進めやすくなります。
  6. 「第1試合を始める」→各端末で提出→教員が締切→結果発表を進めます。
  7. スマートフォンを再読み込みし、同じニックネーム・カード履歴・得点に戻ることを確認します。
この制作環境ではFirebaseエミュレーターと自動操作で検証しています。実際のFirebaseプロジェクト、学校の回線、iPhone／Android実機16台での確認は未実施です。詳細は TESTING.md に記載しています。
TEACHER CONTROL

教員の操作。

場面操作
参加受付QRまたは6文字コードを案内。参加者を確認し、誤登録は名前の「×」で削除します。削除した端末は同じルームへ再登録できません。
ラウンド開始最終指定、勝負カード、制限時間、イベント予定、非公開期間を設定します。おまかせ抽選もこの時点で確定して全員に公開されます。
試合開始「第○試合を始める」で全員の受付とタイマーが始まります。
提出待ち人数のみを表示します。未提出の人がいる場合は、60秒延長するか、未提出0点で締め切ります。期限になるとDBも新規提出を拒否します。
発表「結果発表をスタート」→「次の数字を発表」。小さい数字から、実際に出された数字だけを公開します。最後の数字を見せた後、「結果を確定して順位へ」で集計します。
一括・スキップ残りの数字をまとめて公開して得点確定・ランキング更新へ進みます。確定済みの点数を二重加算しません。
次の試合「第○試合へ」を押します。押した時点から次の提出時間が始まります。
12試合終了公開中ならラウンド順位を表示。非公開中なら順位発表を保留します。次ラウンドを設定するか、ここで最終結果を発表します。過去ラウンドの順位も「ランキング」→「ラウンド別」で確認できます。
やり直し発表前の提出受付中／締切後に「この試合を取り消す」。カードも得点も消費せず、同じ試合番号で新しく受け付けます。発表済みの試合は取り消せません。
投影「投影モード」で文字を拡大。非公開の順位確認は、投影を止めて「管理」タブから明示的に開きます。投影モードへ戻すと非表示になります。
端末を変更した生徒生徒が「端末を変えた・登録を復帰する」から申請。教員の「管理」→「本人を確認して復帰」で元の名前を選び、承認します。元の端末は提出できなくなります。
同名で参加できない「管理」に表示される申請の「申請をリセット」を押し、生徒に名前を修正して再申請してもらいます。
教員PCの再接続同じ教員IDとパスワードでログイン。利用後はホームへ戻り「ログアウト」を押します。以前のルーム一覧の「再開」、または元のルームコードから戻れます。

音は初期状態OFFです。「音 ON」にすると、数字公開時に短い効果音が鳴ります。端末の音量も確認してください。

PLAYER GUIDE

生徒の操作。

  1. QRコードから開くか、公開URLでルームコードを入力します。
  2. 1〜12文字のニックネームで参加します。同名は使えません。
  3. 先生の開始を待ち、1〜15から使っていないカードを選びます。
  4. 勝負カードを使う場合は「⚡勝負カード」をONにします。
  5. 「○を提出」を押し、「提出完了」を確認します。確定後の変更はできません。
  6. 発表を待ちます。「カード履歴」では全員の残りカードと、数字ごとの残り人数を確認できます。
再読み込みしても、同じブラウザー・同じ保存データがあれば復帰できます。別端末や別ブラウザーへ移った場合、保存データを削除した場合は「登録を復帰する」から先生へ申請してください。

匿名認証だけでは、別端末を使った同じ人の追加登録を自動で見分けられません。1人1登録は教員の参加者確認で管理します。ゲーム開始後の新規参加は受け付けません。

GAME RULES

大きく狙うか、小さく抜けるか。

全員が1〜15を各1枚ずつ持ち、同時に1枚提出します。通常点は「カードの数字 ÷ 同じ数字を提出した人数」。小数点以下は切り捨てます。

提出人数1人の通常点
151人15点
152人7点
153人5点
144人3点
56人0点

1ラウンドは12試合。使用した数字は同じラウンド内で再使用できません。通常は3枚を使わずに終了します。未提出は0点で、カードと勝負カードは消費しません。

得点の順番

① 通常点人数で割り、切り捨て
→
② イベント2倍や加点を適用
→
③ 勝負カード単独2倍・被り0点
特殊ルール効果
勝負カード有効なラウンドに1人1回。誰とも被らなければイベント適用後の得点を2倍。被ったらイベント加点も含めて0点。使わずに終えても構いません。
ダブルスコア通常点を2倍。
ローナンバーボーナス1〜7を出した人の通常点を2倍。
偶数ボーナス偶数カードを出した人の通常点に3点を加算。通常点が0でも+3点。ただし未提出には加点しません。

例：6を単独で提出＋偶数ボーナス＋勝負カード成功＝(6＋3)×2＝18点。15を単独で提出＋ダブルスコア＋勝負カード成功＝60点。

ラウンドと最終順位

ラウンドが変わると1〜15のカードと勝負カードが復活。合計点は持ち越します。最終結果で合計点が最大の人が優勝です。同点は同順位（1位・1位・3位）で、同点優勝もあります。

ランキング非公開

指定中は、自分を含む全員の順位・ラウンド得点・合計得点を画面に表示しません。各試合の点数とカード履歴は引き続き公開します。第12試合が非公開なら、そのラウンドの順位発表も保留。最終結果では公開します。

表示を隠す機能です。履歴を計算して得点や順位を再現することまでは防ぎません。

DATA & ANALYSIS

結果を、次の作戦に。

教員の「試合ログ」または「管理」から「CSVで保存」を押します。確定済みの全ラウンドが1つのCSVに入ります。

主な列意味
round / matchラウンド番号・試合番号
event / ranking_hiddenイベント種類・その試合のランキング非公開設定
player_id / nicknameプレイヤーID・ニックネーム
card / multiplicity提出カード・その数字を出した人数。未提出のcardは空欄
normal_points / event_points切り捨て後の通常点・イベント適用後の点
battle_used / battle_success / missed勝負カード使用・成功・未提出（true/false）

ended_at_utc確定した時刻（UTC）

Googleスプレッドシートでは「ファイル」→「インポート」→「アップロード」からCSVを選びます。文字コードはUTF-8、区切り文字はカンマです。日本語の文字化け防止用BOMと、ニックネームの数式誤認を防ぐ処理を入れています。

ルームは自動削除しません。保存が不要になったら、教員の「管理」→「ルームを削除する」で削除してください。必要なCSVは先に保存します。匿名認証のアカウント記録はFirebase Authenticationで別に管理されます。
TROUBLESHOOTING

困ったとき。

「Firebaseの初期設定が必要です」と出る

③で生成したconfig.jsに置き換えてアップロードしたか確認します。ファイル名がconfig (1).jsになっていないかも確認してください。

教員IDでログインできない

メール／パスワード認証が有効か、Authenticationに「小文字のID@teacher.no15.invalid」でユーザーを登録したか、パスワードが合っているかを確認します。教員の利用許可がない場合は、Realtime Databaseのteachers配下に、そのユーザーのUIDを真偽値trueで登録してください。Firebase未設定の表示が出る場合は③のconfig.jsを設定してください。

参加できない／permission_denied

匿名認証が有効か、database.rules.jsonをRealtime Databaseへ公開したか確認します。Firestore用ルールとは別です。提出時だけ発生する場合は、期限・確定済み提出・使用済みカード・引継ぎ後の古い端末を確認します。

名前が同じで参加できない／申請を直したい

教員の「管理」にある該当の「申請をリセット」を押します。生徒画面に入力欄が戻るので、異なる名前で再申請します。

参加受付や提出人数が止まる

教員PCがオンラインで、そのルームの画面を開いているか確認します。再接続後、受信済みの提出人数を再同期します。

スマートフォンの接続が切れた

「提出完了」と表示された提出は保存済みです。「送信を確認しています」の間は完了が未確認です。接続を戻して結果を確認してください。再接続が締切後になった未保存の提出は拒否されます。

GitHub Pagesが404になる

Settings→Pagesがmain / (root)か、index.htmlがリポジトリ直下かを確認します。アップロード直後は公開処理の完了を待ちます。Actionsタブで処理結果も確認できます。

学校の回線で動かない

Firebaseの公式SDK配信元（www.gstatic.com）、認証サービス、Realtime Databaseへの通信が必要です。教員PCとスマートフォンで同じ公開URLから初回テストを行い、ネットワーク管理担当者へ利用可否を確認してください。

無料でどこまで使える？

公式のSpark上限はRealtime Database同時接続100、保存1GB、ダウンロード10GB/月です。ブラウザーのタブも接続として数えられます。1ルーム17接続は接続数の範囲内ですが、複数クラス同時利用や長期保存では使用量を確認してください。

ゲームの途中でルールを変えたい

得点・イベント・非公開設定はラウンド開始時に固定します。次ラウンドの設定画面で変更してください。提出時間の延長・受付再開は発表前に行えます。
